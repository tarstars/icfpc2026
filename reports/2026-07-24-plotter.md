# Plotter: Generated Symmetric Bresenham Machine

Date: 2026-07-24

Problem: `0c3e3d4d-2901-45f1-81cf-5704d49c9139` (`plotter`), scored by
`max(width,height)^2 × average ticks`.

## Architecture

The first complete candidate uses small, explicit protocol stages:

1. Five stream rooms transform `(x0, y0, x1, y1)` into
   `(N, N, dy, 2*err, dx, sx, 32*sy, address)`.
2. An error-test room evaluates the two symmetric Bresenham inequalities and
   emits step code 1, 2, or 3.
3. An error-update room applies `2*dy`, `2*dx`, or both while preserving the
   state-ring order `(dy, 2*err, dx)`.
4. An address room applies the same step code to
   `(sx, 32*sy, address)` and emits every pixel address.
5. Router, plot, and swap rooms write color 15 and commit with SWAP 0, so
   frames do not persist between rounds.

Both state machines count exactly `max(dx, abs(dy))` updates in their
backpacks. The initial address is plotted before those updates, producing
exactly one more pixel than the step count.

The implementation is in a new module so the protected earlier driver sketch
remains untouched.
