# Little Little Man: judge-safe global row squeeze

Date: 2026-07-27

Problem: `little-little-man`

Status: exact generated candidate, 14/14 public locally; not submitted by GPT.

## Project scoring definition

Per `docs/grading.md`, this footprint-tick problem is scored as:

```text
max(width, height)^2 × average ticks across all test cases
```

Width and height are the bounding box of the entire program. All comparisons
below use that definition, not rectangular area and not tick count alone.

## Result

The accepted `llm_codex_01` machine is 749×25,797. A scan found 2,448 rows
whose only glyphs are spaces and vertical pipe segments. Deleting all of them
breaks timing/capacity, so the rows were split into 32 balanced contiguous
groups and judged in combinations.

The retained deletion set removes 2,217 rows: groups `0..3`, `5`, and `8..31`.
Groups 4, 6, and 7 remain.

## Structural and binding evidence

The candidate retains:

```text
145 rooms
231 pipes
143 men
minimum pipe length 2
```

Both `littleman.server_compat.validate_layout` and
`littleman.alexey_pipecheck.check` pass.

Every pipe instruction was normalized by `(room index, instruction index,
opcode, logical pipe index/set)`, excluding absolute coordinates. The accepted
and candidate machines have identical 13,299-entry signatures:

```text

```

The smallest nearest-pipe margin remains three cells.

## Negative results

- Replacing retained group 5 with the equally sized group 4 produced the same
  footprint but only the first public case passed; subsequent cases reached
  the tick cap.
- Removing all 107 globally deletable columns after the safe row deletion was
  rejected before behavioral judging: the logical binding fingerprint changed
  and the smallest resolution margin fell from 3 to 1. Columns would not reduce
  the binding footprint dimension anyway because height remains 23,580.

These results reinforce that blank-line deletion is not automatically safe:
pipes are delay lines and capacity buffers, and Manhattan distances choose
lowercase pipe operations.

## Reproduction

From a checkout with Git LFS materialized:

```bash
PYTHONPATH=src python \
  experiments/gpt-llm-squeeze/build_candidate.py /tmp/llm_gpt_rows.man
sha256sum /tmp/llm_gpt_rows.man

PYTHONPATH=src python \
  experiments/gpt-llm-squeeze/verify_candidate.py
```

The verifier rebuilds the candidate, runs structure/layout/binding gates, then
judges every public case in a fresh child process and computes score using the
formula in `docs/grading.md`.
