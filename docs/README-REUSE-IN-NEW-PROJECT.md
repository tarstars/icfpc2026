# Что скопировать из этого проекта в новый похожий (и куда)

Инструкция переноса для будущего контеста/оптимизационного проекта с
Claude и другими агентами. Порядок = порядок действий в первый час.

| # | взять отсюда | положить туда (в новом проекте) | зачем |
|---|---|---|---|
| 1 | `docs/alexey-next-project-CLAUDE.md` | **`CLAUDE.md` в корень** | Единственный файл, который Claude Code читает автоматически при старте каждой сессии. Заполнить в нём секцию «Проект» (судья, сабмит, дедлайн, ssh-имя быстрой машины). |
| 2 | `docs/alexey-contest-playbook.md` | `docs/contest-playbook.md` | Развёрнутый рецепт, на который CLAUDE.md ссылается первой строкой: метод, ворота сабмита, §7 — полная механика общения агентов с шаблонами писем. |
| 3 | `coordination/templates/` (4 файла) | `coordination/templates/` | Готовые шаблоны message/status/task/handoff. Создать пустые `coordination/status/` и `coordination/messages/<имя-агента>/` для каждого агента. |
| 4 | `docs/two-agent-protocol.md` | `docs/agent-protocol.md` | Нормативный протокол (авторства tarstars) — если агентов больше двух, читается один раз; краткая версия уже в §7 плейбука. |

Больше НИЧЕГО не копировать: весь остальной код здесь специфичен для
littleman (симулятор, squeeze, piperoute, resolveaudit). Их переносимые
ИДЕИ (зонды заселённости, бисекция против судьи, статический аудит-оракул,
resumable-раннер для машины человека) описаны в плейбуке словами — в новом
домене их надо написать заново под его структуры данных, это часы, не дни.

Чек-лист первого часа после копирования:
1. `git init` + удалённый репозиторий — он будет шиной обмена агентов.
2. Заполнить секцию «Проект» в CLAUDE.md.
3. Обёртка сабмита, пишущая полный ответ сервера в файл рядом с артефактом.
4. Каждому агенту: `claim` с write set в `coordination/messages/<агент>/`.
5. Скрипт standings-свипа (ранги + разрыв до соседа) — цели брать из него.
