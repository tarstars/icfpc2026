# Как быстро повторить это в следующем контесте (Claude + агенты)

Написано по итогам ICFPC 2026 (wheezards, 39/268). Это НЕ про littleman —
это переносимый рецепт организации работы человека с Claude и несколькими
агентами над оптимизационным контестом. Скопируй файл в новый проект в
первый час.

## 1. Инфраструктура первого часа

- **Один репозиторий = шина обмена.** Всё — код, кандидаты, результаты,
  переписка агентов — идёт через git. Ни одного артефакта вне репо
  (урок: лучший plotter команды остался вне репо, и я оптимизировал не то).
- **`coordination/`** с первого часа: `status/<agent>.md` (перезаписываемый),
  `messages/<agent>/UTCtimestamp-kind.md` (неизменяемые), явные write sets.
  Правила: сабмитнутые артефакты неизменяемы; новая попытка = новый
  номерной файл; коллизия имён = переименование с префиксом владельца.
- **`.env` с ключами API + submit-обёртка, пишущая ПОЛНЫЙ ответ сервера в
  файл** (`... > submissions/<p>/<name>-submit.json`). Потерянный id
  сабмита — реальная потеря.
- **Машина человека — вычислительный тир.** Ноутбук (M4) оказался в 80 раз
  быстрее облачной коробки на судействе. Паттерн: одно-файловый
  **resumable runner** — фазы пропускаются, если их артефакт уже лежит
  рядом; человек делает `git pull && python3 runner.py && git add/push`.
  На маке линковка C-расширений: `-undefined dynamic_lookup`.

## 2. Метод (главное)

- **Двигай одну вещь → суди → записывай → следующий шаг от предыдущего.**
  Экспериментальная папка на задачу: `stepN.man` + STEPS.md + `check()`,
  печатающий одну строку (размер, ворота, счёт). Никогда не проектируй
  конечную раскладку и не доказывай невозможность до попытки: два моих
  «структурных доказательства пола» пали перед шестью записанными шагами.
  Шаг, ухудшающий счёт, может быть ключевым (окупается через три шага).
- **Меряй, не выводи.** Прежде чем сохранять/менять любую величину —
  зонд. Пик заполнения труб отличил хранилище от транспорта и дал очки в
  обе стороны. Каждое «измеренное дно» устаревает после любого сдвига.
- **Дешёвый оракул > модель.** Если полная проверка дешёвая (секунды) —
  **бисекция изменений против судьи** (subset-sum 2.45x, pathfinder).
  Если дорогая (минуты) — сначала статический аудит-оракул
  (resolveaudit: 68 с против 15-минутного судьи), судья только финалу.
- **Отрицательный результат с числами — это deliverable.** Ложится в
  worklog + сообщение агентам: трижды за контест это удержало других от
  сжигания тех же часов (packing floor, закон n²/(2s), «кадр+1»).
- **Цели выбирай по standings, не по интуиции**: очки живут в разрывах
  рангов. Самый дешёвый ранг ночи стоил 0.33% счёта. Скрипт: для каждой
  задачи — наш ранг, счёт соседа сверху, требуемый множитель.

## 3. Ворота перед каждым сабмитом (без исключений)

1. Структура: счётчики компонентов до/после; **дифф мультимножества длин
   труб** — любое молчаливое укорочение = риск ёмкости.
2. Правила сервера, которых нет в локальном симе — собирай их списком с
   первого отказа (у нас: одна труба у input-комнаты, min длина 2, запрет
   общих стен). Каждое стоило кому-то сабмита; после — проверялось gates.
3. Полный локальный судья + fuzz на границах ограничений (все размеры,
   экстремумы, все количества раундов). Задача с «tick cap» проходит
   публичные и виснет на приватных — гоняй адверсариальные кейсы.
4. Сабмит по standing authorization: улучшение проверено → шлём без
   вопросов; нет улучшения, но шаг логичен → в эксперимент-папку.

## 4. Работа с несколькими агентами

- Явный **claim** с write set'ом при входе; **ack** на передачи; progress
  без ack. Всё письменно в репо — новая сессия/модель продолжает без
  потерь (авто-сжатие контекста переживается именно так).
- **Делись инструментами и порогами, не только результатами**: мой squeeze
  дал claude 1.04x на его matmul; его контрпример (snake) спас мой
  subset-sum; его box-фрейминг поправил мой вывод о «линейном победителе».
  Взаимные adversarial-проверки — лучший каталитизатор.
- Дублирование лечится дешёвле предотвращения: правило «новый файл +
  префикс владельца» разрулило обе коллизии за минуты.
- Человек в цикле: короткие точные наблюдения человека («две стрелочки
  бесполезные», «подвинь трубу вправо») конвертировались в очки — агент
  обязан проверять их измерением, а не спорить по памяти.

## 5. Технические грабли окружения (сэкономят час каждая)

- ssh-agent сокеты протухают: живой ищи `ls -t /tmp/ssh-*/agent.*`;
  `core.sshCommand` с прибитым сокетом — обходить `GIT_SSH_COMMAND=ssh`.
- `pkill -f <паттерн>` убивает собственный shell, если паттерн есть в
  команде. Убивай по PID.
- Фоновые процессы: только `python3 -u`, вывод в файл, НЕ через `| tail`
  (буферизует до конца). Периодический прогресс печатай сам.
- Git LFS: файл в 132 байта с `version https://git-lfs...` — указатель,
  не артефакт. Проверяй ДО оптимизации.
- Локальный judge может быть C-backed: патчи python-класса не сработают —
  зонды гонять через чистый python-sim явно.

## 6. Чему учит счёт

24.592 очка = сумма из ~16 задач по ≤2. Выиграли не прорывы (их не было),
а **ширина**: 1.1–2.5x на восьми задачах руками четырёх агентов за сутки.
Стоимость точки резко растёт у «дна»; дешевле всего — задачи, которых
твой инструментарий ещё не касался (pathfinder дал 1.09x за 40 минут).
