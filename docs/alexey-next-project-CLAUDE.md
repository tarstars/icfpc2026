## Первым делом
1. Прочитай `docs/contest-playbook.md` — это выжимка удачного контеста
   (ICFPC 2026, 39/268): метод, ворота, протокол агентов, грабли.
2. Прочитай `docs/worklog.md` (если уже есть) — текущее состояние.
3. Проверь `coordination/messages/` — почта других агентов.

## Правила работы (проверены контестом, не обсуждаются)
- **Шаги**: двигай одну вещь → проверь оракулом → запиши в
  `experiments/<тема>/` (stepN + STEPS.md) → следующий шаг от предыдущего.
  Не проектируй конечное состояние и не доказывай невозможность до
  попытки. Шаг без выигрыша, но логичный — сохраняй и продолжай.
- **Меряй, не выводи**: перед сохранением/изменением любой величины —
  зонд. «Измеренное дно» устаревает после каждого сдвига — перемеряй.
- **Сабмит**: улучшение, прошедшее все ворота (структурный дифф, полный
  оракул, fuzz на границах ограничений) — отправляй сам, без вопросов;
  полный ответ сервера — в файл рядом с артефактом. Артефакты неизменяемы:
  новая попытка = новый номерной файл.
- **Отрицательный результат с числами — deliverable**: в worklog и в
  сообщение агентам, чтобы никто не жёг те же часы.
- **Цели выбирай по standings**: очки — в разрывах рангов; сначала задачи,
  которых твой инструментарий ещё не касался.
- **Агенты**: механика целиком — §7 плейбука (транспорт = git; claim с
  write set при входе; неизменяемые письма `messages/<я>/UTC-kind.md`,
  kind'ы claim/question/blocker/handoff требуют ack; чужие файлы не
  трогать — только новые с моим префиксом; почту читать каждый заход;
  инструменты и контрпримеры отдавать самому).
- Наблюдения человека проверяй измерением сразу — они дешёвые и часто
  верные.

## Технические грабли (см. §5 плейбука за деталями)
`python3 -u` для фона и никогда `| tail`; kill по PID, не pkill по
паттерну; живой ssh-agent — `ls -t /tmp/ssh-*/agent.*`; LFS-указатели
проверять до оптимизации; патчи sim-класса не видят C-бэкенд оракула.
