## Design summary

Three cell values per signed-64 word, as **signed 21-bit fields** rather
than the offset base-`2**21` scheme in the feasibility report. A value in
`[-1_000_000, 1_000_000]` fits exactly in a signed 21-bit field, so fields
sit raw in bits `[0,21)`, `[21,42)`, `[42,63)`. Masking each field to 21 bits
before shifting it in keeps bit 63 clear (so words never wrap, and a
negative value in field 0 or 1 cannot sign-extend over the fields above it)
and makes a cleared memory the plain word `0` -- the ring seeds with 34
zeros instead of a 19-digit literal.

`addr // 3` and `addr % 3` come from one `/` with `B = 3`. With
`shift = 21 * (addr % 3)`:

- read: `(word << (43 - shift)) >> 43`; the arithmetic right shift does the
  sign extension, so no mask and no bias are needed.
- write: `(word & ~(MASK21 << shift)) | ((v & MASK21) << shift)`.

Both need only two live values at a time, which is why they fit in A and B.

Topology `I -> P1 -> HEAD -> P2 -> STATION -> O`, with
`STATION <-> RELAY` closing the 34-word ring. One station on the ring
instead of `memory_01`'s three. The relay room exists only because a pipe
may not have the same room as source and destination.

## Measurement that should change the plan

Profiling `memory_01` (instrumented `Machine._execute`, public "interleaved
cells"): 125 operations, `sum(k) = 6108` ring relays, 55,482 ticks, so
**~8.9 ticks per circulating item**; the three ring rooms account for ~93% of
all instruction executions but run concurrently, so the per-item cost is one
station lap, not three.

Consequence: deleting a ring room saves no ticks, and the only lever is the
number of circulating items. Packing takes that case from 6108 relays to
1994 (3.06x), which is exactly where the 2.34x tick win comes from.

## Failed alternatives (do not re-derive)

- Offset (`+1_000_000`) base-`2**21` packing: correct, but costs a 19-digit
  seed literal and a bias add/subtract per access.
- `new = old + (nf - of) << shift`, and `/`-based peel/reassemble
  (`hi*Q + nf*P + lo`): both need three live values at some step, so they
  need an extra room on the ring path -- which raises the per-item lap cost,
  the one number that matters.
- A first layout at 47 x 37 reached the same 4159 average ticks but footprint
  2209; only the ring routing changed to reach 37 x 37.
- `@` re-entered by a relay lap is a nop, so the man keeps his heading and
  hits the wall. `@` must sit off the lap.

## Assumptions and known limits

- The live-score projection in the report (~24.2M) is an **extrapolation**
  from `memory_01`'s local:server tick ratio of 4.243, not a measurement.
- Private cases are unseen; the candidate is verified against a Python
  oracle on seeded random streams, all-100-cell coverage and worst-shape
  ring distances, but nothing is hardcoded to the public data.
- The station is the only room with 2 in / 2 out pipes.
  `test_station_pipe_resolution_is_unambiguous` re-derives all eleven `r`/`s`
  resolutions from the parsed machine; if the layout is moved, that test is
  the guard.
- Ring capacity is 26 + 17 = 43 pipe cells for 34 words. Shortening either
  ring pipe below a combined 34 deadlocks the machine.
